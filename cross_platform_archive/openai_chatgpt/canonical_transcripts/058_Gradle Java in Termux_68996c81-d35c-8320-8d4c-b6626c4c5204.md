- `settings.gradle`
- `build.gradle`

./gradlew build      # compile + test + jar

# Track B — Android’s native “Terminal” (Developer option)

This shell is “toybox” with no package manager. You can still run Java/Gradle, but you must provide binaries yourself (or work inside a proot distro). Two workable options:

**Option 1: Drop in prebuilt JDK + Gradle in /data/local/tmp**
1) Push zips via `adb` from a computer (easiest), or download directly on device.
2) Unzip somewhere writable, e.g.:
```
cd /data/local/tmp
mkdir jdk gradle && unzip openjdk17.zip -d jdk && unzip gradle-8.9-bin.zip -d gradle
export JAVA_HOME=/data/local/tmp/jdk
export PATH=$JAVA_HOME/bin:/data/local/tmp/gradle/gradle-8.9/bin:$PATH
java -version
gradle -v
```
3) From there, the exact same Gradle steps as Track A:
```
mkdir ~/hello-gradle && cd ~/hello-gradle
gradle init --type java-application --dsl groovy
./gradlew run
```
(If `~` isn’t defined, pick any writable dir under `/data/local/tmp`.)

**Option 2: Use a proot distro inside the native terminal**
- Bootstrap a minimal userland (e.g., Debian/Ubuntu rootfs) into a writable path and `proot -0 -S` into it; then `apt` install `openjdk-17-jdk` and `gradle`. This mirrors a tiny Linux and behaves like Track A. (It’s heavier, but cleaner.)

# Gradle + Java: mental model in 60 seconds

- **Gradle Wrapper (`gradlew`)**: per-project launcher that downloads the right Gradle version and isolates you from system Gradle. Always use `./gradlew ...`.
- **`settings.gradle`**: project name + included modules.
- **`build.gradle`**: dependencies, plugins, tasks.
- **`src/main/java`**: your code; **`src/test/java`**: tests.
- **Key commands**:
  - `./gradlew run` (with the application plugin)
  - `./gradlew build` → creates `build/libs/<name>.jar`
  - `./gradlew dependencies` → view dep graph
  - `./gradlew help --task <task>` → what a task does

---

# Quick JNI/Native note (only if you meant “native code”)
- For *Android apps*, JNI usually means NDK. That’s overkill on-device.
- On Termux, you can still build native libs with:
```
pkg install -y clang make cmake
```
Then wire JNI in Gradle (application plugin → not Android) or just build C/C++ binaries for CLI tools. If you later want true Android apps, you’ll want the Android SDK/NDK on a PC or in a cloud dev box.

# Common snags (and fixes)

- **“Permission denied” running `gradlew`**  
  `chmod +x gradlew`

- **Gradle can’t download (network blocked)**  
  Try again on stable Wi-Fi or set Gradle properties for HTTP proxy if you’re behind one (`~/.gradle/gradle.properties`).

- **Out of space / slow**  
  Clean often: `./gradlew clean build` and prune Gradle caches: delete `~/.gradle/caches` if needed.

- **JAVA_HOME not set**  
  On Termux with `openjdk-17`, usually fine. Else:
  ```
  export JAVA_HOME=$PREFIX/opt/openjdk
  export PATH=$JAVA_HOME/bin:$PATH
  ```
