**Short answer:**  
**Windows Security Audit Event ID 4688 logs *every* new process creation — which includes processes launched by shortcuts, scheduled tasks, and system events.** Shortcuts and scheduled tasks don’t have special audit IDs of their own; they simply *cause processes to start*, and **4688 is the event that records those starts**. 

---

## 🔍 What Event ID 4688 *actually* represents  
Event ID **4688** (“A new process has been created”) is generated by the **Microsoft‑Windows‑Security‑Auditing** provider whenever Windows starts a new process. It records:

- **Executable path**  
- **Command line** (Windows 8.1+/Server 2012 R2+)  
- **Parent process**  
- **User account / logon session**  
- **Token elevation type**  
- **Process ID**  

This makes it one of the **core forensic events** for tracking execution, privilege escalation, malware activity, and lateral movement. 

---

## 🧩 How shortcuts relate to Event 4688  
A **shortcut (.lnk)** is not a process — it’s a pointer.  
But when you double‑click a shortcut, Windows resolves it and **launches the target executable**, which *creates a new process*. That process creation is what triggers **4688**.

Examples:  
- Clicking a desktop shortcut → launches `app.exe` → **4688 logs app.exe**  
- A malicious .lnk file → launches PowerShell with hidden arguments → **4688 logs powershell.exe with full command line**  

This is why shortcuts are often used in malware: **4688 exposes the real payload**.

---

## ⏰ How scheduled tasks relate to Event 4688  
A **scheduled task** is just a trigger mechanism.  
When the task runs, Windows Task Scheduler launches the configured action (usually an EXE, script host, or command). That launch is a **new process**, so:

- Task Scheduler (`taskeng.exe` or `svchost.exe` hosting Schedule service) becomes the **parent process**  
- The launched program (e.g., `cmd.exe`, `powershell.exe`, `backup.exe`) becomes the **new process**  
- **4688 logs the creation**, including the command line and parent process name  

This is why 4688 is essential for detecting:

- Persistence via scheduled tasks  
- Hidden PowerShell or script execution  
- Tasks created by malware to run payloads at logon or system startup  



---

## 🖥️ How system events relate to Event 4688  
Many Windows components automatically spawn processes:

- Services starting at boot  
- Windows Update  
- Background maintenance tasks  
- Explorer launching child processes  
- Remote administration tools  
- Script engines (PowerShell, WScript, CScript)  

All of these generate **4688** because they create processes.  
This allows analysts to correlate:

- **4688** (process start)  
- **4689** (process exit)  
- **4624** (logon session)  



---

## 🧠 Why all three — shortcuts, scheduled tasks, and events — show up in 4688  
Because **they all ultimately cause Windows to start a process**, and **4688 is the universal audit event for process creation**.

| Mechanism | What it does | Why 4688 logs it |
|----------|--------------|------------------|
| **Shortcut (.lnk)** | Points to an executable | Double‑click launches a process |
| **Scheduled Task** | Triggers an action at a time/event | Task Scheduler starts a process |
| **System Event** | OS component starts a process | Any process creation is logged |

---

## 🧷 Why this matters (especially for forensics)  
Because **4688 is the single most important event for reconstructing execution chains**:

- Detecting malware launched via .lnk files  
- Detecting persistence via scheduled tasks  
- Detecting privilege escalation (via elevation type)  
- Detecting suspicious parent/child relationships  
- Detecting hidden PowerShell or script execution
